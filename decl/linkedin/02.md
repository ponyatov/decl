# v-agent programming in `decl`
## a sample of compact event-driven code

In the original article here: https://habr.com/ru/articles/554014/ there is a short description of VAOP programming methodology admitted by @valrakitine 

There is a problem that many modern programmers does not differ code with algorithms used in this code. So, v-agent oriented programming (VAOP) is a methodology of writing algorithms, represented as a "v-agent script" which allows a software agent (v-agent) to execute operations coded in "v-agent boxes".

In a classical terms, we have some **State Machine** (=v-agent) executes branches of code (=v-agent boxes) selected by:
- current internal machine **state**, and
- external events

The key goal is to have the algorithm written in a short compact code, understandable by all stakeholders (clients, programmers, computers), which reduces maintenance and adaptation costs. The ultimate aim is to ensure the "immortality" of a software product with minimal modernization investments. It looks like this is more useful for clients (who have to maintain the product long-term) than for developers.

- **Why?** For the convenience of all participants in software creation    
- **What?** Representing an algorithm in a form understandable to all (maybe not skilled) participants
- **How?** All participants use the same algorithm notation, which significantly reduces costs in development, maintenance, and updates. This is claimed to be unique to VAOP, but it looks me can be done with any high-level and more or less formalized language.

Algorithm is a model of actions, but problem in a form of writing this algorithm, and passing them between actors takes part in a project.

The most simple way to write an algorithm is using numerated list where item numbers allows us to reference actions, and jump (pass control) between them.

For item "code" bodies we can use natural language, as example the sum of array `M = [34,45,57,8,14]` can be written as:

0. declare array `M = [34,45,57,8,14]` as input data
1. create variables:
	- array index: `i=0`
	- resulting accumulator: `sum=0`
2. add array element `M[i]` to `sum`
3. increment index: `i = i +1`
4. if index > M size jump line 5
	- else jump line 2
5. the end: `sum` variable contains resulting value: the sum of `M[]`

This form can't be understand by old computers, until we have AI smart enoght to undestand this form:

DeepSeek query: `write pseudo code for sum(M)`

result:
```
0. array M = [34,45,57,8,14]
1. i=0; sum=0
2. sum = sum + M[i]
3. i = i + 1
4. if i > size(M) jump 5 else jump 2
5. end: print(sum)
```

How to make this executable?

- **Today (without general AI)**: Write a small interpreter for this specific numbered-list language (a DSL).
- **Tomorrow (with LLMs)**: An LLM can directly execute your numbered list with a "pseudo-code interpreter" or translate it on the fly to Python/JavaScript, exactly as you suggest.

Also, old days we used standardized block charts for writing this like simple algorithms, and even try to make visual languages such as Dragon to let generic engineers to write code without deep knowledge of machine languages and programming skills. The problem is block chart can be stored in a computer-readable form but totally unreadable for human without special render tool or visual editor which is very complex itself.

v-agent script splits algorithm into multiple v-agent nodes:
- every node has a unique identification name
- every node do some action
- the result of this action is a direction which switches control to some other node

With a `decl` we can write code in a two lines:
```decl
const M:[int] = [34;45;57;8;14] // declare array of ints
out << M.sum                    // just call generic summing method
```

AI-powered translator runs over LLM model has a huge number of code in any known programming languages in its learning data continuum, so there is no any doubt AI not only able to read and understand this code but also can translate it directly to target language we want:

- compile to JS:
```js
const M = [34,45,57,8,14];
console.log(M.reduce((a,b) => a + b, 0));
```
- compile to Python:
```python
M = [34,45,57,8,14]
print(sum(M))
```

If we need to save iteration approach:
```decl
const M:[int] = [34,45,57,8,14] // input
var sum = 0                     // initialized accumulator
for i in M: sum += i            // iteration
out << sum                      // output
```
compile to JS:
```js
const M = [34, 45, 57, 8, 14];
let sum = 0;
for (let i of M) { sum += i; }
console.log(sum);
```

And finally, if we forced to use va-script model:
- vs-script: we can represent finite state machine as `actor`
- nodes: encode algorithm fragments as message handlers **with clear names**
- direction: state transition can be done with message sending to itself

```decl
actor {
	init:
		const M = [34; 45; 57; 8; 14]
		var i = 0; var sum = 0
		self!add                        // send message to actor=self
	add:
		sum = sum + M[i]; i++
		if i > M.size self!end else self!add
	end:
		out << sum; halt
}
```

compile to JS:

```js
/**
 * @brief V-agent style actor for summing array elements
 * @author Dmitry Ponyatov <dponyatov@gmail.com>
 */

class SumActor {
    constructor() {
        this.running = true;
        this.state   = 'init';
        this.mailbox = [];
    }

    /// Send message to self
    send(msg) {
        this.mailbox.push(msg);
        this.dispatch();
    }

    /// Process pending messages
    dispatch() {
        while (this.mailbox.length > 0 && this.running) {
            let msg = this.mailbox.shift();
            this.process(msg);
        }
    }

    /// State machine handler
    process(msg) {
        switch(msg) {
            case 'init':
		        this.M = [34, 45, 57, 8, 14];
		        this.i = 0;
		        this.sum = 0;
                this.send('add');
                break;

            case 'add':
                this.sum += this.M[this.i];
                this.i++;
                
                if (this.i >= this.M.length) {
                    this.send('end');
                } else {
                    this.send('add');
                }
                break;

            case 'end':
                console.log(this.sum);
                this.running = false;
                break;
        }
    }
}

/// Usage
let actor = new SumActor();
actor.dispatch();
```
