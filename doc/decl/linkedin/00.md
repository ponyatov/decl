# `decl`: declarative DSL language
## for writing code-generating AI prompts

Now I'm playing with design of AI-powered SDL language for writing IoT and automation declarative queries generates code for selected target languages & config scripts. The idea is about using free-form syntax and the actor model for describing deployment, behavior and arbitrary contracts about network of interacting MCUs, embedded Linux devices and general purpose elements runs in a cloud, desktop or mobile.

The core idea is a using of script-like language I feel comfortable for myself, using some semantic and syntactic elements relates to F#/OCaml, Python, Erlang/Elixir and Rust, to describe system or firmware I want to get, and produce code in production languages such as JavaScript, embedded C/C++, SQL, etc. This declarative description can be translated by AI (I use free DeepSeek AI chat as a test platform) into code snippets I manually fix and integrate into project code.

This code-style approach looks me more affordable comparing to writing queries in human languages. I can describe for AI syntax & semantics of the DSL I want to use, provide some translation samples, and next AI able to "compile" free-form declarative code fragments into a code can be used in a production code shared with colleagues.

```decl
let name = "decl"
out << 'Hello from {name}!'
```

compile to JS:


# Key features of `decl` DSL
## decl targets embedded firmware and software development

- Multi-Platform Support
	- - **Heterogeneous clusters** combining
		- Linux (x86, RPi3+),
		- Cortex-M MCUs,
		- ESP32C/ESP32S devices,
		- Android mobile devices (phones and HMI panels)
	- **Cross-node messaging** with
		- automatic (de)serialization
		- scheme description and validation using type system with ranges, patterns and guard expressions
- **Actor Model** for Concurrent Systems
	- multi-node parallelism based on async message passing between isolated processes
	- Pub/Sub pattern for system-wide message brokering and data processing
	- State Machines driven by incoming messages and internal actor's state
- Low-Level Memory Control
	- memory segments and absolute memory region bindings for MMIO, DMA, peripherial buffers
	- fixed-size arrays
	- `undef` marker for using large fragments of uninitialized memory
- Low-Level Platform Interop
	- embedded C/C++ code generation
	- side library binding without wrappers
	- Direct hardware registers access with bitfield definitions
	- Interrupt handlers as actor methods
	- Inline assembly support
- **Literate programming**
	- I group code and its description into multiple .md files which makes documentation and code live together
	- Early attempts to use literate programming were killed by limitation of required code ordering (declarations must before use etc). AI context generation can be done by fragments send in any order, so LP can now reborn
	- AI also can understand specification in any programming language and in any human language, so you are not forced to write some spec twice: in human description, and in source code
- Rich **Pattern Matching** and Erlang-like **Binary expressions**
	- pattern matching looks ideal for catching async messages and hardware-related events and process them in specific match branches
	- pattern language with types, ranges and arbitrary guard expressions make declarative code both very compact and very expressive
	- Elixir-like functional polymorphism use pattern templales in place of classical function signatures, so AI-bases translator can take function variant most close to needs in every its call point or ever infer new function variant not described ever
